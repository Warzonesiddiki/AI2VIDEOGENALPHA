# FAILURE / BLOCKER / RECOVERY MATRIX — Required Build Reference

**Use with:** `02_MASTER_PROJECT_RULES.md`, `14_AI_STUDIO_FLASH_EXECUTION_PROTOCOL.md`, and the active phase prompt. This is a cross-cutting product requirement, not a new implementation phase and not a claim that every future defect can be predicted. The builder must implement the failure classes relevant to each phase, add tests, and add newly discovered failures to the project’s evidence/decision records.

## A. Invariants for every failure

1. **Never show success without evidence.** A spinner, HTTP 200, accepted job ID, UI toast, generated text, or exit code alone does not prove a usable file, charge, render, upload, privacy status or publish state.
2. **Preserve the last known-good state.** A failed draft or regeneration must not overwrite an approved script, asset, master render, database or export. Write to temporary/versioned paths and atomically promote only after validation.
3. **Persist enough to resume.** Save stage, versioned inputs, output references/hashes, timestamp, provider/model/API route, attempt count, idempotency/reconciliation reference, last error code, budget reservation, consent/policy record and required next action. Redact keys, OAuth tokens, personal data and private prompt text from logs/diagnostics.
4. **Treat remote side effects as at-least-once unless proven otherwise.** Before a billable generation/upload, persist an operation intent and provider idempotency key where supported. If a timeout/disconnect leaves it unclear whether the provider billed, generated or uploaded, set `unknown_external_effect` and reconcile/query before any retry. Never assume “no response” means “no charge or upload.”
5. **Fail closed on authority or safety uncertainty.** Missing consent, unknown/retired model, stale terms, rights issue, over-cap spend, unsafe path, uncertain public visibility or unresolved source claim blocks the operation. Offer an actionable human/manual route; do not bypass controls to keep the workflow green.
6. **Retries must be bounded and typed.** Retry only documented transient conditions with capped exponential backoff and jitter. Do not retry authentication/permission/validation/policy/rights failures. Respect `Retry-After`. Any retry that might bill must show its possible incremental cost and obey the original scoped grant.
7. **Cancellation is not rollback.** Stop future work and terminate local children safely, but retain completed outputs and clearly report any external operation that may already have completed or incurred a charge.
8. **Any unlisted error follows the same contract.** Classify it, preserve state, prevent duplicate external effects, show a useful message and next action, add a regression test, and update the matrix/traceability record. Never dismiss it as an “edge case” without evidence.

## B. Required persisted status vocabulary

Use separate job/stage status and external-operation status where needed. At minimum support:

- Job/stage: `queued`, `running`, `paused`, `blocked`, `needs_user`, `retrying`, `succeeded`, `failed_recoverable`, `failed_terminal`, `cancelled`.
- External side effect: `not_started`, `pending`, `confirmed_succeeded`, `confirmed_failed`, `unknown_external_effect`, `reconciling`.

The UI and CLI must expose the exact state, last verified checkpoint, actionable reason, whether a charge may have occurred, whether a duplicate is possible, and the safe resume/reconcile action. `succeeded` is allowed only after output/status validation. Do not collapse `blocked`, `failed`, `cancelled` and `unknown_external_effect` into one red/green indicator.

## C. Failure matrix

| ID / boundary | Failure or trigger | Required behavior and recovery | Minimum test/evidence |
| --- | --- | --- | --- |
| B-01 Prompt/context | A required prompt, rule, series bible or repository file is missing | Stop before implementation/claiming coverage; identify the exact missing file and request import. Never infer file contents from its name. | Remove one required context file and verify the agent reports the missing prerequisite. |
| B-02 Prompt conflict | User decision, master rule, phase prompt and code disagree | Preserve data; identify the conflicting statements and source; follow the safer reversible rule; ask one specific question if the choice blocks progress. Update the decision log after resolution. | Fixture with conflicting timezone/provider/approval rules; verify no silent choice. |
| B-03 Context loss or truncation | AI Studio conversation resets, response stops mid-phase, or context limit is reached | Read `docs/ai-build-ledger.md`; verify actual files/tests/diff before continuing; resume from last verified checkpoint only. Do not repeat completed phases or claim unfinished changes passed. | Simulate a stopped response/new session and resume without duplicate migration/provider work. |
| B-04 Build/test failure | Typecheck, migration, test, preview or production build fails | Mark phase `PARTIAL/BLOCKED`; preserve logs; fix in-scope regressions before next phase. Never proceed based on expected or cached success. | Deliberately fail a check and verify the continuation prompt names command, failure and next task. |
| B-05 Official docs unavailable | Provider docs, pricing, deprecation status or policy page cannot be fetched/verified | Do not invent API details. Leave capability `unverified/unconfigured`, implement the adapter boundary/manual import only, and record URL, date, what is unknown and evidence needed. | Disable network/docs and confirm no guessed endpoint/model is enabled. |
| L-01 Runtime prerequisite absent | Node/package manager, FFmpeg/FFprobe, OpenCode, WSL or required OS version missing | Doctor reports the precise missing tool/version and install/repair steps; unrelated local story/project tasks remain usable. Do not simulate a connected capability. | Run Doctor with each executable missing. |
| L-02 Path/permission mismatch | Windows/WSL path conversion, spaces/Unicode, ACL, symlink escape, moved drive or read-only folder | Reject unsafe/out-of-root writes, retain the configured canonical root, show a safe relink/fix path, and never follow a symlink outside the authorized root. | Test spaces, Unicode, case differences, denied access, moved root and symlink escape. |
| L-03 Disk/process failure | Low disk, file-handle exhaustion, FFmpeg crash, app termination or power loss | Stop safely; retain the last committed artifact; clean only app-owned temporary files; mark unfinished local work recoverable/interrupted; allow resume after health check. | Kill worker during write/render; restart and verify no corrupt master is marked complete. |
| L-04 Database/migration failure | Migration fails, is interrupted, or schema is newer/older than the app | Back up before migration; apply transactionally where supported; keep prior database recoverable; refuse to start against a partial/incompatible schema and give rollback/restore steps. | Fresh install, supported upgrade, interrupted migration and failed rollback tests. |
| L-05 DB/filesystem disagreement | DB row points to missing file, or file exists without a committed DB row | Reconcile from a manifest/checksum; quarantine orphan/partial files; never delete or silently substitute user assets. Offer relink/recover actions. | Remove an asset and separately create an orphan; verify each is reported and recoverable. |
| L-06 Backup/export/restore failure | Incomplete archive, checksum mismatch, insufficient space or attempted restore over live work | Verify contents/checksums before commit; restore to a new location first; preserve the original; exclude credentials; explain if provider-side deletion cannot be performed. | Corrupt archive/checksum and low-space restore tests. |
| P-01 Provider setup | Key missing, malformed, expired, wrong project/region, or user denied consent | Mark provider `not_configured/unauthorized/consent_denied`; do not call; keep manual import/local work available. Never log or echo credentials. | Missing, malformed, revoked key and consent-denied tests. |
| P-02 Model/API mismatch | Unknown, retired, preview-shut-down, unsupported or capability-mismatched model/route | Reject before billable call; show exact mismatch, official source/check date and setup path. Do not silently substitute another model or modality. | Attempt an invented and a known-retired ID; assert zero provider calls. |
| P-03 Provider terms/data change | Data-use, retention, geography, pricing or API terms materially change or notice is stale | Pause calls; show the changed notice/source/date and request fresh consent; do not treat old consent as blanket approval for materially different processing. | Mark policy snapshot stale and confirm request is blocked until reconsent. |
| P-04 Network/rate/service error | DNS/TLS/connection loss, 408/429/5xx/provider outage | Classify transient vs terminal; honor `Retry-After`, cap attempts, persist backoff/cancel; surface expected wait and budget effect. | Simulate 429 with Retry-After, 5xx, offline network and TLS error. |
| P-05 Ambiguous provider timeout | Request sent but response/job ID is missing; charge or generation may have occurred | Set `unknown_external_effect`; reconcile by provider request/idempotency ID, usage log or manual check. Do not reissue automatically if duplicate billing is possible. | Drop connection after request dispatch; verify no blind second call. |
| P-06 Malformed/partial model output | Invalid JSON/schema, empty text, incomplete image/video/audio, unexpected safety refusal | Validate before persistence/approval; bounded repair only when known not to repeat paid generation or with explicit incremental-cost approval; otherwise preserve error/partial output and request correction/import. | Malformed JSON, empty payload, incomplete asset, refusal and repair-cap tests. |
| P-07 Budget unknown/overrun/concurrency | Cost unavailable, price changed, retries/concurrent jobs may exceed cap | Require explicit manual maximum for unknown costs; reserve against per-run/episode/monthly caps atomically before calls; pause before next call when headroom is insufficient. Never raise cap automatically. | Concurrent jobs at one remaining unit; unknown price; retry-induced cap overrun. |
| P-08 Safety/policy refusal | Provider blocks content or request violates safety/provider policy | Stop that request; show a non-sensitive explanation and safe revision path; never attempt evasion by paraphrasing, switching accounts or disabling safety controls. | Provider-policy rejection fixture; verify no retry/evasion. |
| P-09 Partial batch success | Some images/clips/voices complete, others fail | Persist each item independently; show completed/failed/unknown counts and costs; allow retry of only confirmed failed items; never regenerate completed items by default. | Batch with mixed success, failure and timeout. |
| P-10 Silent provider fallback | Primary model unavailable, degraded, or newer model selected by alias | Do not silently change model, quality profile, data route or terms. Ask/require an explicitly configured fallback; show cost and data notice for that fallback. | Disable primary and verify no alternate provider is called without authorization. |
| C-01 Research unavailable | No search provider/network/source | Mark research unavailable/not required; use operator-provided evidence or keep claims out of narration. Model memory and model-suggested URLs are not verified evidence. | Offline test with a real-world claim in the draft. |
| C-02 Malicious/unsafe source | Prompt injection, private-network URL, redirect, oversized archive/page or malicious file | Treat source as untrusted; block private/loopback/link-local targets and unsafe downloads; sanitize, size-limit and store provenance only. Do not follow embedded instructions. | Prompt-injection, SSRF, redirect, ZIP-bomb and oversized-input tests. |
| C-03 Contradictory/unverified claim | Sources conflict, are stale, or fail to support exact claim | Mark disputed/unverified; cite the relevant evidence and limitation; exclude or rewrite as fictional/qualified content until human fact-check. Never invent a citation. | Contradictory-source and unsupported-claim tests. |
| C-04 Canon/originality failure | Hard-rule conflict, repeated plot/template, possible protected-work similarity | Block or warn with exact conflict/similarity and affected canon; require showrunner decision/explicit retcon. Do not auto-rewrite or certify legal originality. | Canon conflict, reused beat and retcon impact tests. |
| C-05 Upstream revision | Approved script/shot/voice changes after downstream production | Mark only dependent prompts, media, audio, captions and renders `stale`; preserve old version; prevent packaging mismatched artifact versions. | Edit script after render and verify dependency invalidation. |
| M-01 Voice issue | Unsupported language/accent, pronunciation error, wrong speaker, clipped or incomplete TTS | Do not treat audition as full-episode approval; preview voice; retain text/audio alignment; let user correct pronunciation or import a licensed take. Re-record affected segments only. | Wrong-language, pronunciation, missing segment and partial TTS tests. |
| M-02 Image/video mismatch | Provider returns wrong aspect, duration, fps, resolution, character reference or silent video | Probe actual output; reject/flag mismatch; preserve prompt/reference; offer a targeted regeneration only within budget. Never infer intended format from a filename. | Wrong dimensions/duration/fps/no audio/reference mismatch tests. |
| M-03 Caption/timing mismatch | Captions do not match final narration, overlap, overflow safe area or drift after edits | Derive captions from final approved audio/timing, validate, show preview, mark stale on audio/script edits; export accurate SRT/VTT only after checks. | Timing drift, Unicode, speaker labels, safe-area and edit invalidation tests. |
| M-04 Render failure | FFmpeg exit failure, missing stream/file, corruption, black/silent output, invalid codec/aspect/duration | Keep prior approved master; fail QC with exact FFmpeg/FFprobe evidence; do not mark package ready. Rerender from last valid stage. | Real short smoke render plus injected missing audio/file/codec/exit failures. |
| M-05 Rights/consent unknown | Asset, voice, music, likeness, font or generated output rights cannot be evidenced | Keep asset quarantined/not cleared; request license/consent or replace with owned/approved media. Do not treat a checkbox or provider output ownership as full clearance. | Missing rights record blocks commercial package test. |
| Y-01 OAuth/channel failure | User denies/revokes consent, wrong account/channel, expired scopes/token | No upload; show actual selected identity/scopes in masked form; let user reconnect or use manual Studio. Never switch channel silently. | OAuth denial/revocation/scope/channel-switch tests. |
| Y-02 Upload timeout/duplicate risk | Connection drops before/after upload response | Distinguish confirmed failure from `unknown_external_effect`; reconcile by upload/session/video ID and Studio before retry. No duplicate automatic upload. | Drop connection at each resumable-upload boundary. |
| Y-03 Privacy/status mismatch | Requested private but response/Studio says otherwise, or returned status absent | Hold and block public release; show requested vs actual state; reconcile in Studio. Never label upload private/public without evidence. | Response mismatch, missing status and Studio disagreement tests. |
| Y-04 Quota/channel/schedule failure | API quota or separate channel upload cap reached; invalid timezone/DST boundary | Record which limit failed; wait/use manual Studio without evasion; require explicit IANA timezone and re-confirm scheduled local time before action. | Separate API/channel limit errors; timezone and boundary tests. |
| Y-05 Policy/UI field unavailable | Required disclosure/audience/monetization field cannot be set or current policy is ambiguous | Stop at preflight and give tailored Studio instructions; no scraping/click automation or inferred policy decision. Hold public release until a person confirms current Studio choices. | Unsupported field and ambiguous synthetic-disclosure tests. |
| S-01 Secret exposure | Key/token appears in UI, logs, prompt, export or Git | Immediately stop affected job, redact/rotate/revoke the credential, remove it from tracked artifacts/history where feasible, preserve sanitized incident evidence and notify the operator. Never print the secret while diagnosing. | Secret scan across logs/build/export/Git test fixture. |
| S-02 Untrusted input/command | Path traversal, archive exploit, prompt injection, shell metacharacter, unsafe HTML | Reject/contain input, avoid shell-string interpolation, sanitize rendered content and keep operations within allow-listed roots. No generated command is executed without a safe typed interface. | Security tests for path/archive/XSS/command/SQL injection and SSRF. |
| S-03 Unauthorized external action | Agent attempts paid call, publish, deletion, cap increase or secret read without grant | Deny server-side, log a redacted audit event and keep project unchanged; require fresh human approval scoped to the precise action. | Agent/CLI attempts each prohibited operation. |

## D. Persistent AI Studio build-progress ledger

After the project repository exists, maintain `docs/ai-build-ledger.md` as a small, secret-free developer continuation record—not app data or a user-facing page. Do not serve or bundle it to end users. Update it after each phase, interruption, failed test or scope change. It must contain:

- project name, current branch/revision if available, last update time;
- active prompt/phase and exact prerequisites satisfied/not satisfied;
- phase status (`NOT STARTED`, `IN PROGRESS`, `PARTIAL`, `BLOCKED`, `VERIFIED`);
- files/migrations changed and concise implementation summary;
- exact commands executed and observed results, with unrun checks listed separately;
- decisions/assumptions and unresolved user questions;
- provider configuration status by modality, with no key, token, private source or unpublished script text;
- open blockers/failure IDs and the last known-good checkpoint;
- one exact next action/prompt.

In a new AI Studio chat or after truncation, first read this ledger and inspect the actual code/diff/tests; then continue from the last verified checkpoint. Never trust the ledger if it conflicts with the repository or actual test output. Do not dump secrets or large story/private media content into the ledger.

## E. Completion requirement

For each failure row applicable to a phase, trace **risk → detection → safe state → recovery action → test → user-facing docs**. Add new discovered failures to the matrix and the application’s `docs/requirements-traceability.md`/release evidence. The complete matrix is a systematic minimum, not a guarantee against every future provider, operating-system, platform, security or human error. Residual risks must be disclosed, not hidden by a green dashboard.
