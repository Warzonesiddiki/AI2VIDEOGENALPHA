# Ternfall React Accessibility

1. Check loading, empty, error, conflict and stale-source states; cancel or ignore outdated async responses after project/episode changes.
2. Use semantic headings, labeled controls, keyboard-visible focus, appropriate status/error announcements and reduced-motion support; review contrast and overflow.
3. Exercise desktop and mobile viewports, keyboard-only interactions and no-external-network behavior in an isolated browser fixture. Prefer role/name selectors.
4. Automated scans and emulation do not replace screen-reader, real-device, cross-browser or manual accessibility testing; state those gaps.
